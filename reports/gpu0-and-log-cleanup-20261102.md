# GPU-маршрут и очистка журналов STS — 2 ноября 2026

Выполнено для `sts-matrix-support` с сохранением чужих сервисов. Отдельно получено разрешение добавить маршрут STS в общий LiteLLM; изменение сервера модели пользователь отклонил.

## Маршрут и GPU

- До изменения юридический и финансовый маршруты использовали `legal-chat-qwen38-int4` → `vllm-lab` на физической GPU 1.
- Добавлен отдельный `sts-qwen-gpu0` → `openai/qwen3.8` → `http://vllm-h200:8000/v1`. Сервер сообщает модель `qwen3.8`; его запуск использует `Qwen/Qwen3.8-27B-FP8`.
- Сохранены все 11 прежних маршрутов и прежний образ общего LiteLLM. Добавлена только сеть доступа к существующему серверу GPU 0, сохранённая также в Compose шлюза.
- Созданы отдельные ограниченные ключи бота и Flowise. Новый маршрут возвращает HTTP 200; попытка старого маршрута GPU 1 для каждого нового ключа — HTTP 403. Ключи не выгружались.
- Переключены все 8 STS-потоков / 16 модельных узлов, включая оба активных Agentflows. Идентификаторы комнат, контракт, топология и защита Prediction API сохранены.
- У бота и нашего Flowise выставлено `CUDA_VISIBLE_DEVICES=0`; сами эти контейнеры работают на CPU и не имеют Docker-доступа к GPU.
- Физическая GPU 0 подтверждена для дочернего процесса `vllm-h200` через NVIDIA UUID/индекс и PID. Сервер модели продолжает иметь прежний Docker-доступ к обеим картам. **Жёсткая маска сервера не изменена по явному отказу пользователя**; это не утверждение полной аппаратной изоляции.
- Серверы `vllm-h200` и `vllm-lab` не перезапускались: сохранены ID контейнеров и PID.

Для добавления маршрута общий шлюз LiteLLM перезапускался. Первая попытка не прошла ограниченную проверку готовности и была откачена; после увеличения времени ожидания повторное применение и проверки завершились успешно. Другие маршруты не менялись.

## Журналы и дампы

- Удалены 60 старых файлов журналов приложения/сборок (416112 байт, около 0,42 МБ). Датированные логи Flowise удалялись только старше семи дней.
- Пересозданы шесть собственных приложений на прежних образах; старые Docker-журналы удалены самим Docker, без внешнего обнуления файлов движка. Размер этих журналов в предварительном измерении был около 414 МБ. Новые журналы при итоговой проверке: 107323 байт.
- Для шести приложений применён `json-file`, `max-size: 10m`, `max-file: 3`. Два контейнера PostgreSQL не пересоздавались; эта ротация к их небольшим журналам не применялась.
- Сохранены текущие журналы приложения, ключи, базы, документы, активный индекс и архив восстановления.
- В проверенных собственных каталогах отдельных старых SQL/pgdump/backup-дампов не обнаружено. Найденный 25-байтный SQL-файл — сценарий инициализации БД, он сохранён.

## Multica и границы изменений

Собственных контейнеров Multica не обнаружено. `devplat-backend-1`, `devplat-frontend-1`, `multica-opencode-runtime` принадлежат Compose-проектам `devplat` и `opencode-docker`; они сохранены. Другие контейнеры и образы не удалялись. Глобальные prune-команды не запускались, GPU 1 и её сервисы не изменялись.

## Проверки

- Восемь сервисов проекта работают, настроенные healthcheck успешны.
- Element, Flowise и Synapse: HTTP 200. Бот восстановил Matrix-сессию и проверенный локальный семантический индекс.
- Два настоящих запроса принудительно проведены через Agentflows и новую модель, без обхода локальным шаблоном: юридический — 15.95 с, финансовый — 7.369 с; оба приняты цепочкой проверок, по восемь найденных фрагментов. Юридический использовал доработку, финансовый прошёл первый аудит.
- Это проверка интеграции двух сценариев, не новая массовая оценка юридической/финансовой точности. Тексты ответов и реальные переписки наружу не выводились. Новые сообщения в пользовательские комнаты Matrix для этого теста не отправлялись.
