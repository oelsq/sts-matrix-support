## Что исправлено

- В одинаковом наборе бытовых вопросов подбор ожидаемого документа улучшился с 80/104 до 104/104. Например, больничный, наследство после пропуска срока, передача телефонного номера рекламщикам, гарантийный ремонт, изменение аренды, реструктуризация, банковские коды. У обоих специалистов сохранён доступ к публичным законам.
- Появился разбор явно названной статьи конкретного кодекса. Отсутствующая статья не заменяется другой нормой. Неоднозначный запрос без названия акта не считается однозначно распознанным.
- Исправлены ложные приоритеты: покупка квартиры не должна превращаться в возврат товара, семейный бюджет — в задержку зарплаты, повышение аренды — в возврат залога. Жалоба на незаконную комиссию в SuperApp допускает общие нормы; короткий тарифный вопрос остаётся в рамках продукта.
- Проверка чисел различает проценты, тенге, МРП, доллары/евро, годы, месяцы, рабочие и календарные дни. «Пять лет» больше не подтверждает «5%». Сохранена поддержка числительных словами, диапазонов и нулевой ставки. Эта эвристика не доказывает правильность каждого вывода и не заменяет юридическое толкование.
- При просьбе сообщить банковский SMS-код немедленная памятка по официальному материалу доступна в обоих чатах до обращения к модели.
- Исправлен dev-proxy frontend: порт 8010 и удаление префикса `/api`. Добавлен lock-файл, используется npm ci. Vite обновлён до 6.4.5, React-плагин 4.7.0; Docker-сборщик — Node 22. Production bundle и HTTP проверены после обновления.
- API отклоняет пустые/слишком длинные сообщения и заголовки, неизвестные статусы и отрицательную пагинацию. Для допустимого длинного сообщения оставлен запас длины ответа. Убраны устаревшие FastAPI startup и Pydantic class Config.

## Работа в закрытой сети

Добавлены `compose.offline.yml`, `config/litellm/offline.yaml` и `scripts/offline_preflight.py`. Автономный запуск выбирает локальную модель, не требует NITEC API key, запрещает неявную загрузку/сборку образов и использует внутреннюю Docker-сеть. Внешние модельные адреса отклоняются статической проверкой. Инструкция: `docs/OFFLINE.md`.

Это **не результат приёмки в реальной изолированной сети**. Веса, GPU-инференс и образы готовятся отдельно. Внешняя сеть действительно отключается на инфраструктурном уровне, затем повторяются запросы из Element. Локальное имя upstream не удостоверяет, что за ним не скрыт удалённый прокси.

## Как повторить

```bash
python -m venv .venv
.venv/bin/pip install -r matrix_support_bot/requirements.lock.txt
DATABASE_URL=sqlite:////tmp/sts-audit.sqlite3 .venv/bin/python -m pytest -q
.venv/bin/python scripts/evaluate_answers.py --output /tmp/retrieval.json
cd support-frontend
npm ci
npm run build
npm audit
cd ..
.venv/bin/python scripts/check_local_http.py --output /tmp/local-http.json
```

Для проверки офлайн-конфигурации заполнить локальные параметры `.env` по `docs/OFFLINE.md`, затем `.venv/bin/python scripts/offline_preflight.py`. Источники и сценарии находятся в `offline_knowledge/manifest.json` и `config/answer-evaluation.json`.

## Что остаётся подтвердить на VM

1. Реальную генерацию обоих специалистов через Agentflows V2, точность фактов/ссылок, качество казахского и русского текста, продолжение беседы и черновики документов.
2. Сравнение доступных локальных моделей на одинаковых вопросах с ручной оценкой. В этом прогоне **модель не заменялась и веса не обучались**; соответствие уровню ChatGPT/Gemini не заявляется.
3. Доставку Matrix и переключение между пятью сотрудниками каждого департамента на настоящих аккаунтах.
4. Полную автономность с выключенным внешним каналом, реальную задержку, очередь и нагрузку. 100–500 обращений в день этой проверкой не удостоверены.
5. Сборку Docker для целевой архитектуры (включая обновлённый Node), nginx, PostgreSQL, права доступа и резервное восстановление.

Наличие зелёных тестов означает, что пройдены эти конкретные проверки. Оно не гарантирует безошибочность финансового/юридического совета или готовность всей инфраструктуры к эксплуатации.
