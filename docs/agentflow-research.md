# Повторный поиск и проверка ответа

## Путь вопроса

Element → Python-бот → поиск в локальных документах → Agentflow V2 → проверенный ответ → Element.

Для типовых вопросов бот может сформировать ответ прямо из подходящего фрагмента документа. В таком случае модель и Flowise не вызываются; это отражается в поле `mechanism` отчёта. Расчёт по таблице также выполняет Python до вызова модели.

## Когда Agentflow запрашивает новый поиск

В существующей схеме из 13 узлов сохранены подготовка черновика, проверка утверждений и одна ветка исправления. Если проверка отклоняет ответ или сохраняет только часть, итоговый JSON может содержать до четырёх подсказок `retrieval_hints`. Это поисковые данные, а не подтверждение правовой нормы. Контроль полноты также проверяет сохранение применимых исключений по ГЭСВ, пределов гарантии вкладов, объекта автострахования и сообщённого гражданского договора.

`quality_reply.py` выполняет максимум один дополнительный локальный поиск и затем повторно запускает защищённый Agentflow с новым набором фрагментов. Старый черновик не становится источником. Общий бюджет двух запусков — 180 секунд. Если поиск ничего не добавил, повторного запуска нет. Если второй запуск неудачен, сохраняется ранее подтверждённая часть с исходными ссылками; при отсутствии такой части используется ограниченная практическая помощь.

Повторный поиск находится в Python-боте, а не в отдельном поисковом узле Flowise. В Executions могут появиться два выполнения одного Agentflow. Отдельный запуск схемы из интерфейса Flowise не включает внешний повторный поиск и локальный калькулятор.

## Ограничения источников

- Сохраняются исходный банк, продукт и область вопроса; подсказка проверяющей модели не может переключить банк.
- Ссылки на другие статьи разрешаются только при явном указании того же закона или кодекса. Интернет-запросы не выполняются.
- Известные даты начала/окончания действия учитываются, некорректные даты блокируют материал. Отсутствие дат не доказывает актуальность закона.
- Для банковских тарифов с давней или неизвестной датой проверки выводится предупреждение. Оно не заменяет обновление тарифа.
- Неизвестный тип договора требует условного вывода и уточнения; отсутствие письменного договора само по себе не означает договор ГПХ.

## Расчёт без арифметики модели

В чате доступна команда `!расчёт`. Ответ содержит шаблон: фактически полученная сумма, валюта, дата получения, полный график дат/сумм и отдельные расходы вне графика. Имена и реквизиты не нужны.

`cashflow_calculator.py` использует Decimal: сумма платежей + отдельные расходы − полученная сумма. Он не рассчитывает ГЭСВ, законность комиссий или будущие штрафы. Смешанные валюты, неполный график и неоднозначные суммы требуют исправления входных данных. Удержанные до выдачи расходы нельзя повторно прибавлять к уже уменьшенной сумме выдачи.

## Проверка качества

`config/challenge-cases.json` содержит 125 кандидатов: варианты формулировок существующих тем, расчёты и примеры с гражданским договором. Это 23 семейства сценариев, а не 125 независимых юридических заключений, проверенных специалистами.

```sh
python scripts/evaluate_golden.py --cases config/challenge-cases.json run --output /private/path/local.json
python scripts/evaluate_golden.py --cases config/challenge-cases.json run --live flowise --progress --output /private/path/live.json
```

Закрытый отчёт хранит ответы, точные использованные фрагменты, механизм, число повторных поисков и ошибки генерации. Автоматические проверки отделены от экспертных оценок. До реального решения юриста или финансиста статус остаётся `awaiting_specialist`, экспертные баллы — пустыми. Полные отчёты и секреты не следует публиковать в Git.

## Обновление действующих схем

`scripts/upgrade_agentflow_quality.py --refresh` сначала создаёт закрытый план до/после, затем `--activate` применяет его с проверкой неизменности исходной схемы. `--rollback` возвращает сохранённую версию. Идентификаторы узлов, модели, доступ по ключу, маршруты комнат и расположение узлов сохраняются. Незнакомая топология требует отдельной проверки.

Проверка второй моделью помогает находить ошибки, но не гарантирует правильность правовой интерпретации, особенно при использовании одной и той же модели для черновика и проверки. Для важных выводов нужны актуальные источники и экспертная оценка.
