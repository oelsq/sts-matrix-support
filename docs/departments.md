# Передача живым сотрудникам и смена сотрудника


## Выбор и смена

- `!сотрудники` — показать настроенных сотрудников этого департамента, текущего назначенного и команды выбора. Команда не создаёт комнат и не рассылает сообщения сотрудникам.
- `!юрдеп1` … `!юрдеп5` — выбрать юридического сотрудника по номеру.
- `!финдеп1` … `!финдеп5` — выбрать финансового сотрудника по номеру.
- `!другой` — следующий сотрудник по списку, кроме текущего. Например, после сотрудника 2 будет сотрудник 3, после 5 — сотрудник 1. Это выбор по порядку, не оценка занятости.
- `!помощь` — подсказка команд.

**Пример:** Руслан пишет в финансовом чате `!финдеп2`, общается со вторым сотрудником, затем возвращается в чат ИИ и пишет `!другой Прошу ещё раз проверить расчёт`. Появится отдельная комната с сотрудником 3. Можно сразу выбрать `!финдеп5`. Юридический департамент работает так же. Назначения двух департаментов независимы.

Команды выполняются в чате ИИ. В комнатах людей бот не отвечает и после присоединения первого участника выходит. Оттуда пользователь возвращается в чат ИИ для выбора следующего сотрудника.

## Контекст и история

При первом явном запросе бот передаёт последний вопрос пользователя, ответ ИИ с пометкой о возможной ошибке и комментарий. Этот исходный контекст ограниченного размера сохраняется в локальной SQLite для повторной передачи при смене сотрудника и перезапуске. При смене переносится исходный контекст обращения и текущий комментарий; **бот не возвращается в старую комнату и не читает переписку людей**. Необходимые дополнительные сведения пользователь сообщает новому сотруднику сам.

В новую комнату изначально приглашаются только пользователь и выбранный сотрудник. Старая комната и её участники сохраняются: смена не отзывает старый доступ и не закрывает спор. Нельзя считать предыдущего сотрудника удалённым из старой комнаты. Переключение обратно к ранее выбранному сотруднику создаёт новую комнату, если он не текущий. Повторный выбор текущего сотрудника или `!человек` открывает существующую комнату без повторной рассылки контекста.

Существующие комнаты не заменяются при миграции базы. Предыдущие назначения сохраняются в `handoff_archive`; бот продолжает игнорировать сообщения во всех этих комнатах. Уникальный ID команды Matrix сохраняется в `handoff_requests`, чтобы повтор события после перезапуска не переключал сотрудника ещё раз. При ошибке создания сохраняется прежнее назначение; при ошибке передачи контекста повтор завершает уже созданную комнату. Сначала завершите незавершённую передачу через `!человек`, затем меняйте сотрудника.

## Ограничения

Начальные обращения без выбора распределяются по кругу. Список и номер не подтверждают присутствие, рабочие часы или срок ответа. Учёта занятости, общей очереди, SLA и автоматического закрытия пока нет. Работает один экземпляр бота: блокировки в памяти не обеспечивают координацию нескольких реплик. Комнаты демонстрационные, без E2EE; пользователь и сотрудник имеют права управления своей комнатой и могут вручную менять участников.

Логины новой установки: `@jurdep:demo.local`, `@jurdep2`–`@jurdep5:demo.local`; аналогично `@findep` и `@findep2`–`@findep5`. При другом `MATRIX_SERVER_NAME` меняется часть после двоеточия. Локальные пароли — `runtime/accounts.txt`. Используйте разные профили браузера для пользователя и сотрудника.
