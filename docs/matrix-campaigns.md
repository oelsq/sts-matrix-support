# Массовые проверки через настоящий Matrix

`config/matrix-cases-20261029.json` содержит 280 синтетических сценариев. SHA-256 исходного файла зафиксирован в `matrix-cases-20261029-freeze.json` до первого запуска. В набор входят прежние регрессии и новые расчёты, вопросы о командах и продолжения диалога. Это не независимый экспертный экзамен.

`config/matrix-release-cases-20261029.json` — 25 целевых регрессий последнего выпуска, выбранных после исходного прогона. Их нельзя представлять как новые независимые вопросы.

## Как выполняется проверка

- `scripts/run_vm_case_suite.py` — инструмент именно существующей VM `sts-vm-06`: использует её имена контейнеров, сети и выделенный каталог в `sts-matrix-support/stages`. Он создаёт временного бота, генератора и четыре тестовых аккаунта. Рабочий бот продолжает работать.
- `scripts/matrix_case_suite.py` — создаёт две приватные комнаты, отправляет вопросы через Synapse и получает реальные сообщения бота. Два обработчика последовательно ведут независимые пользовательские цепочки. Между сценариями отправляется `!новый`; предыдущие вопросы диалога тоже действительно отправляются.
- Окончательный ответ сопоставляется с запросом по `org.sts.request_id` и точному ключу окончательного сообщения. Срочное промежуточное сообщение не засчитывается как окончательный ответ.
- Полные ответы, HTML и тестовые идентификаторы остаются в закрытом отчёте на VM. В конце временные контейнеры удаляются, аккаунты деактивируются, credentials, env и SQLite-состояние очищаются. При неудачной очистке credentials сохраняются для восстановления; запуск не объявляется успешно очищенным.

Подготовьте новый каталог `stages/<имя-прогона>` с `run_vm_case_suite.py`, `matrix_case_suite.py` и выбранным набором под именем `cases.json`. На этой VM:

```sh
python3 /home/admin_sts/sts-matrix-support/stages/<имя-прогона>/run_vm_case_suite.py \
  --stage /home/admin_sts/sts-matrix-support/stages/<имя-прогона> \
  --candidate <локальный-проверяемый-образ>
```

Если `--candidate` отсутствует, проверяется текущий образ рабочего бота. Существующий каталог с результатами или credentials повторно не используется. На другой установке сначала адаптируйте имена контейнеров, сети и корень; этот инструмент не является обязательным шагом обычного запуска проекта.

## Что означают результаты

Доставка, наличие текста, автоматические критерии и юридическая правильность — разные показатели. Отчёт разделяет технические ошибки, явные отказы проверки, дубли и несовпадения содержания. Сценарии `delivery_and_usefulness_only_no_factual_score` не проверяют достоверность утверждений. Статус эксперта автоматически не создаётся.

`scripts/summarize_matrix_suite.py` экспортирует только публичные ID сценариев, числовые измерения и коды замечаний. Текст ответа, HTML и Matrix-идентификаторы не экспортируются. Подтверждённые дефекты критериев записываются отдельно, исходная оценка сохраняется.

`scripts/prepare_matrix_review.py` восстанавливает точное соответствие между цифровыми ссылками `[1]` в доставленном сообщении и `Фрагмент: <ID>` в карточках источников. Только затем можно запускать `review_synthetic_answers.py` внутри VM. Отсутствующее соответствие не подменяется придуманным источником. Дополнительная ИИ-сверка той же семьёй моделей не является независимым заключением юриста или финансиста.
