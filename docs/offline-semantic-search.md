# Смысловой поиск без интернета

`KnowledgeStore.search` сначала выполняет прежний поиск по словам и юридическим темам. Дополнительно `semantic_search.py` сравнивает вопрос с локальными векторами текстов. В выдаче до восьми фрагментов сохраняются первые пять лексических результатов; добавляются не более двух новых смысловых результатов. Единственный лексический результат из другого правового акта также сохраняется. Затем повторно применяются ограничения; перед генерацией дополнительно подбираются применимые исключения. Если точный поиск не нашёл ничего, векторы не подставляют случайную норму. Для тарифов, неизвестного банка и явно указанной статьи используется прежний точный поиск.

Права доступа, предметная область, банк/продукт и применимость проверяются до вычисления смыслового рейтинга. Вектор не даёт разрешения на чтение закрытого документа. При несовпадении хеша корпуса, модели, ID фрагментов или файла векторов включается поиск по словам с предупреждением в журнале.

Модель: `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, зафиксированная ревизия и контрольные суммы в `config/semantic-model.json`. ONNX int8 на CPU, 384 измерения, максимум 128 токенов на окно. Для фрагмента индексируются до трёх перекрывающихся окон. Это ограниченная смысловая подсказка; полный текст продолжает обрабатывать лексический поиск. Русский язык предусмотрен моделью; качество казахского требует отдельного испытания. Это **модель поиска**, а не замена генератора ответов Qwen.

## Подготовка на машине с интернетом

Из корня проекта, в окружении Python 3.12:

```sh
python -m pip install -r matrix_support_bot/requirements.lock.txt
python -m pip install --no-deps -r matrix_support_bot/requirements.semantic.lock.txt
python -m pip check
python scripts/fetch_semantic_model.py --output runtime/semantic/model
python scripts/build_semantic_index.py --model runtime/semantic/model --output runtime/semantic/index --threads 2
```

Загрузчик проверяет закреплённые хеши; при расхождении существующего файла останавливается. Перед переносом в закрытую сеть подготовьте wheels под ОС и архитектуру целевого сервера. Не копируйте macOS wheels на Linux.

В закрытой сети переносите `runtime/semantic/model`, `runtime/semantic/index`, проверенный Docker-образ и исходный корпус одной версии. Во время ответа загрузок нет. Модель, векторы и пользовательские запросы не публикуются в Git. Кеш до 128 векторов запросов живёт только в оперативной памяти; ключи — хеши, текст вопросов в нём не хранится.

## Запуск переносимой сборки

```sh
docker compose -f docker-compose.yml -f compose.semantic.yml build bot
docker compose -f docker-compose.yml -f compose.semantic.yml up -d --no-deps bot
```

`compose.semantic.yml` меняет только бот: добавляет зависимости и два монтирования только для чтения. Для действующей VM с иной Compose-конфигурацией используйте её рабочий файл и соответствующие абсолютные пути. Не заменяйте всю конфигурацию сервера переносимым примером.

После изменения PDF, текста, метаданных или алгоритма нарезки пересоберите индекс тем же парсером, который будет работать в образе. Проверка индекса намеренно откажется использовать прежние векторы для нового корпуса. Для отключения уберите только семантический overlay/переменные и перезапустите бот; лексический поиск остаётся рабочим.

Лицензия модели Apache-2.0. Сохраняйте README и текст лицензии вместе с перенесёнными весами. Источник: https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2

Повторяемые проверки: 330 прежних поисковых сценариев и `config/semantic-paraphrase-cases.json` с 16 новыми перефразировками. Последний набор проверяет только нахождение подходящего документа в восьми результатах; он не подтверждает правильность статьи или интерпретации. Сравнивайте обе версии поиска и сохраняйте неудачи.
