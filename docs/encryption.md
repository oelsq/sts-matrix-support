# Шифрование Matrix и бота

Бот поддерживает E2EE напрямую через matrix-nio 0.26 и Rust vodozemac. Pantalaimon для этого не нужен. Режим включается явно; старые комнаты и старая история автоматически зашифрованными не становятся.

## Граница защиты

В новой зашифрованной комнате Element шифрует вопрос, а бот расшифровывает его как участник. Ответ шифруется перед отправкой в Synapse. Сервер Matrix хранит шифротекст событий.


## Для пользователя

1. В существующем чате отправьте `!лично`. Бот пригласит в две отдельные личные комнаты: ЮрАгент и ФинАгент. Примите приглашения. Старые сообщения туда не копируются.
2. Перед первым ответом подтвердите устройство бота через SAS: сравните **все семь эмодзи** на стороне Element и оператора бота. При любом несовпадении отмените проверку.
3. Пишите вопросы в личной комнате. При отсутствии ключа или доверия бот сохраняет сообщение в защищённой очереди и ждёт; открытым текстом в эту комнату не отвечает.
4. Новый браузер/ноутбук — новое устройство. Его нужно проверить отдельно. Не удаляйте ключи и не сбрасывайте доверие без плана восстановления.


В личной комнате участвуют только её владелец и бот. Владелец не может добавлять других людей. Комнаты разных пользователей разделены. Федерация и гостевой доступ выключены, история доступна с момента вступления.

Команды `!человек`, `!юрдеп2`, `!финдеп3`, `!другой` сохраняются. В защищённом режиме создаётся новая зашифрованная комната с выбранным сотрудником. Первоначальный контекст передаётся только после фактического входа обоих людей и проверки их устройств; затем бот выходит. Старые комнаты и переписка людей сохраняются. Сохранённая копия контекста передачи в базе бота удаляется через 30 дней; это не удаляет сообщения в самой комнате.

## Если в Element нет кнопки проверки бота

У matrix-nio отсутствуют cross-signing и in-room SAS; интерфейс некоторых версий Element не показывает проверку такого бота. Pantalaimon использует тот же класс старых SDK и официально архивирован 08.04.2026. Его установка сама по себе этот недостаток не устраняет.

Предусмотрен отдельный ручной способ для **одного** устройства. Владелец открывает сведения о своей настоящей сессии Element и сравнивает Session ID и **полный публичный Ed25519-отпечаток** с данными оператора. Это публичный ключ проверки устройства; пароль, recovery key и экспорт секретных ключей не нужны. После явного подтверждения совпадения оператор выполняет:

```bash
docker exec sts-team-demo-bot-1 python /app/crypto_operator.py \
  --state /app/handoff_state/crypto fingerprint \
  @user:server DEVICE_ID PUBLIC_ED25519_FINGERPRINT --compared-on-device
```

Команда повторно получает ключ устройства, проверяет точное совпадение и сохраняет доверие через SDK. При несовпадении, неизвестном пользователе, удалённом устройстве или отсутствии решения доверие не устанавливается. Способ не создаёт cross-signing-подпись и не обещает зелёную отметку аккаунта в Element. Для другого браузера сравнение выполняется заново.

Перед отправкой ответа бот требует хотя бы одно проверенное устройство каждого получателя. Остальные непроверенные сессии исключаются из раздачи ключей локальной блокировкой SDK; аккаунт и сами браузерные сессии не удаляются. Успешная последующая проверка конкретного устройства снимает его локальную блокировку и обновляет исходящую криптографическую сессию. При отсутствии проверенного адресата ответ остаётся в защищённой очереди.

Операторские приглашения предварительно проверяют полный Matrix-ID и наличие локального профиля. Отображаемое имя вроде `ruslan` может отличаться от настоящего Matrix-ID; несуществующий адресат не должен создавать новые комнаты.

## Новая установка

Требуется Docker Compose с поддержкой `!override`/`!reset` (на проверенной VM — 2.40.3).

```bash
python3 scripts/setup.py init
```

`init` создаёт `runtime/secrets/state_key` с правами 0600. В `.env` установите:

```dotenv
MATRIX_E2EE_ENABLED=1
MATRIX_PRIVATE_AI_MODE=optional
```

`setup.py` подключит `compose.secure.yml`. При самостоятельном вызове Docker Compose указывайте этот файл явно. Для бота нужны сборочный аргумент `WITH_MATRIX_E2EE=1`, криптографические зависимости и проверенный патч SDK; профиль задаёт аргумент сборки.

- `optional`: прежние комнаты работают как раньше; `!лично` приглашает в новые защищённые комнаты.
- `1`: прежние комнаты служат входом; содержательные вопросы перенаправляются в личные комнаты. Старый вопрос автоматически не копируется.

Профиль привязывает собственные веб-порты к loopback и снимает публикацию PostgreSQL. Перед применением к существующей установке проверьте её зависимости. Доступ с другого ноутбука — через собственный SSH/Teleport-туннель или согласованный HTTPS-адрес.

## Проверка устройств оператором

Для новой установки:

```bash
docker compose exec bot python /app/crypto_operator.py --state /app/state/crypto status
```

На существующей VM контейнер и путь состояния другие:

```bash
docker exec sts-team-demo-bot-1 python /app/crypto_operator.py --state /app/handoff_state/crypto status
```

Команда показывает публичные идентификаторы и ожидающие SAS-проверки, без токенов и закрытых ключей. После сравнения с Element выполните `match <transaction_id>`, при несовпадении — `reject <transaction_id>` вместо `status`. Подтверждать всё автоматически запрещено. Чтобы начать проверку со стороны бота, выполните вместо `status` команду `request @user:server DEVICE_ID`: пользователь получит запрос в Element и сможет сравнить эмодзи. Идентификаторы его известных устройств показаны в `status`. Оператор может отправить приглашения командой `invite @user:server --domain both`; пароль пользователя для этого не нужен.

## Ключи, хранение и откат

- Постоянное устройство и Olm/Megolm-сессии: каталог `crypto/` внутри состояния бота. Не удалять и не подменять при обновлении.
- Ключ `state_key` хранится отдельно от базы, не в Git. Он защищает поля очереди, контекст, токен сессии и криптографические pickle-данные. Идентификаторы комнат, метки времени и другая служебная метаинформация не скрываются.
- Для восстановления нужны **и ключ, и соответствующий каталог состояния**. При утрате/подмене ключа запуск прерывается. Новый device_id не создаётся молча вместо прежнего.
- Перед миграцией остановите только своего бота и сохраните зашифрованный бэкап `state_backup.py backup --state ... --key-file ... --archive ...`. Режим `verify` проверяет подлинность. `restore` разрешён только в пустой каталог.
- Один старый образ без соответствующего старого состояния не является рабочим откатом: прежний код не умеет читать зашифрованную базу.

`runtime`, `.human-handoff-state`, ключи, токены и криптографические базы не добавляются в Git. Для закрытой сети заранее перенесите собранный образ и зависимости; отсутствие доступа в интернет не должно приводить к переустановке или сбросу устройства.

## Исправления совместимости SDK

`matrix_support_bot/crypto_sdk_compat.py` меняет только известную версию и известный SHA256 исходника nio:

1. Commitment SAS кодируется неполным base64, как требует протокол, вместо hex ([upstream #570](https://github.com/matrix-nio/matrix-nio/issues/570)).
2. MAC объявляется как `hkdf-hmac-sha256.v2`, соответствующий используемому примитиву vodozemac.
3. Семь готовых индексов emoji vodozemac используются напрямую, без повторного преобразования из байтов.

При неожиданной версии или контрольной сумме сборка останавливается. При обновлении SDK патч нужно пересмотреть. Криптографические примитивы самостоятельно не реализуются. Проверки двух одинаковых nio-клиентов недостаточно: совместимость дополнительно проверяется настоящим Element с его браузерной криптобиблиотекой.

## Основные файлы

| Файл | Назначение |
|---|---|
| `matrix_crypto.py` | Криптоклиент, постоянное устройство, доверие, ожидание ключей |
| `matrix_verification.py` | Запрос SAS, ручное сравнение, MAC и завершение проверки |
| `private_rooms.py` | Личные зашифрованные комнаты и изоляция владельцев |
| `matrix_transport.py` | Шифрованная отправка, запрет открытого резервного пути |
| `matrix_delivery.py`, `matrix_inbox.py` | Очередь, курсор sync, порядок и защита от повторной доставки |
| `state_cipher.py`, `state_backup.py` | Защита чувствительных полей и зашифрованный бэкап |
| `human_handoff.py` | Защищённая передача выбранному сотруднику |
| `compose.secure.yml` | Профиль E2EE, ключ и сетевые привязки новой установки |

Личные комнаты наследуют текущий прямой режим своего специалиста. Шифрование меняет доставку сообщений, сохраняя выбранную модель, инструкции и настройки генерации.
