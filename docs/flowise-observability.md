# Измерения Agentflows V2 и повторная сверка ответов

`matrix_support_bot/workflow_metrics.py` извлекает только разрешённые числовые показатели из ответа Flowise. Для известных ID 13-узлового графа фиксируются число исполнений, число доступных измерений и длительность этапа. Названия узлов из интерфейса, входы/выходы, тексты, пользователи, комнаты, сессии, credentials и абсолютные timestamps в показатели не входят.

Модельные узлы Flowise возвращают `data.output.timeMetadata.delta` в миллисекундах. Наши пять CustomFunction дополнительно измеряют исполнение чистого JavaScript через `Date.now()`. Flowise сериализует их результат в `data.output.content`; клиент разбирает только ограниченный JSON известных JS-этапов и извлекает из него `timeMetadata`. Ошибочный, слишком большой или отсутствующий показатель остаётся `null`, не становится нулём. Данные модельного ответа не разбираются как произвольный JSON метрик.

Измеряемые определения этапов: `prepare`, `draft`, `unitize`, `audit`, `gate`, `repair`, `unitize_repaired`, `audit_repaired`, `gate_repaired`. Старт, условие перехода и два определения DirectReply в установленной версии Flowise собственной длительности не публикуют. Для них сохраняется факт исполнения и явно отсутствующее время. Эти накладные расходы входят в общее время запроса; точное разложение всех узлов до миллисекунды не заявляется.

В рабочем логе событие `Flowise workflow summary` содержит направление и числовую сводку. `model_nodes_executed` означает исполнения модельных узлов графа, не количество успешных запросов к провайдеру. `repair_used` показывает посещение ветки доработки. Общее `elapsed_ms` включает HTTP, ожидание Flowise и обработку ответа; отдельный `delta` модельного узла уже этого времени не охватывает полностью. p95 разных этапов нельзя складывать.

В синтетическом отчёте `evaluate_golden.py` сохраняет `workflow_metrics` отдельно от закрытого текста ответа: по одной записи на попытку workflow. Повторный поиск может вызвать второй workflow. Отказ проверки сохраняет числовые измерения завершённого workflow. Отказ соединения/тайм-аут может не содержать серверных показателей; это не нулевая длительность модели. Реальная беседа не нужна для анализа нагрузки.

## Эксперимент с обратной связью для доработки

В ветке `experiment/agentflow-review-20261025` код `claim_gate.js` добавляет в закрытую обратную связь `claim_feedback`: ID не прошедшей строки, ссылки S из неё и валидные выбранные локаторы S/Q. Локатор включается только если принадлежит текущему источнику и его точная выдержка совпала. Это кандидат для повторного чтения, не автоматическая правка ссылки и не одобрение вывода. Исправленный текст снова проходит те же проверки цитат, чисел, обязательных условий и полноты проверок. Экспериментальные инструкции и эта передача локаторов не активированы в основном выпуске: преимущество по реальным модельным проверкам пока не установлено.

## Дополнительная ИИ-сверка

`scripts/review_synthetic_answers.py` проверяет тело ответа, отделённое от приложенного списка источников. Точные fragment ID в ссылках приводятся к S по переданной выдаче; незнакомые ссылки и заполнители не присваиваются случайному источнику. Карточка сохраняет fragment ID и версию, чтобы связь оставалась проверяемой. Закрытые обоснования остаются на VM; наружу допускается только отдельная сводка с числами, публичными ID тестов и кодами. Человеческих экспертных одобрений этот инструмент не создаёт.

Новый набор `config/heldout-hardening-20261025.json` сформирован до изменений; хеш и обязательство первого запуска после заморозки кода записаны в соседнем `*-freeze.json`. Он авторский, не внешняя экспертная проверка. Если результаты используются для следующей настройки, набор становится регрессионным. Не меняйте вопросы/критерии ради зелёного результата и не называйте 40 вопросов 40 успешными модельными ответами: отчёт отдельно показывает попытки, принятые ответы и локальные механизмы.

## Словесный возраст и проверка чисел

Воспроизведён ложный отказ: источник содержал «шестнадцатилетнего возраста», ответ — `16 лет`, а числовая проверка не распознавала число в прилагательном. Теперь полные словесные формы возрастов 12–18 лет приводятся к тем же числам внутри Python- и JS-проверок. Текст ответа и дословная цитата не переписываются. Чужой возраст 15 или 17 не подтверждается выдержкой о 16; отрицания и слова, задающие границы, сохраняются. Составной фрагмент другого слова не становится числом. Это нормализация записи значения, не новая норма права и не проверка всей юридической интерпретации.
