# Полезный ответ до предложения сотрудника

Обычный ответ больше не получает автоматическую приписку `!человек`. Команды департаментов и выбор любого сотрудника сохранены. Предложение сотрудника появляется по явному желанию пользователя, при сообщении о неудовлетворительном ответе или конкретном серьёзном риске (например, задержании или заседании суда сегодня/завтра). Одного слова «срочно» для такой рекомендации недостаточно. Экстренная памятка о раскрытых банковских данных по-прежнему сначала объясняет, что сделать сразу, не ожидая чата.

## Как проверяется содержимое

Общая подготовка `matrix_support_bot/local_reply.py` вызывается и из бота, и из оценочного скрипта. Она различает уточнение, объяснение по фактически найденным положениям, организационный пример письма, ответ при отсутствии источника и необходимость реальной модели. Эти механизмы нельзя выдавать друг за друга.

`answer_usefulness.py` ищет очевидные проблемы поверх проверки цитат/чисел:

- Ответ состоит из направления к сотруднику; длинный список источников не считается содержательной помощью.
- Обычный ответ начинается с рекомендации департамента или шаблонного отказа вместо помощи по существу.
- Пользователь просит письмо, а получает лишь совет его составить. Распознаются разные адресные поля, включая «Арендодателю» и «От арендатора».

Плохой сгенерированный ответ отправляется на повторную попытку. Если проверка повторно не пройдена, бот даёт доступную ограниченную помощь с нужными уточнениями. При сбое генерации непроверенный черновик не отправляется: сохраняются организационные шаги и сообщается о недоступности сервиса. Для запрошенного письма лимит повторной попытки увеличен до 320 слов. Проверка не оценивает смысл каждого предложения и не гарантирует юридическую правильность.

## Масштабная оценка

```bash
python scripts/evaluate_helpfulness.py --include-retrieval-cases --archive --output /tmp/helpfulness.json
```

Основной банк `config/helpfulness-evaluation.json` содержит 62 сценария содержания: работа, письма, покупки, аренда, кредиты, коллекторы, мошенничество, семейные вопросы, справка и планирование денег. Вместе с 234 сценариями поиска после удаления одинаковых вопросов/контекстов получается 273 уникальных сценария. Новый скрипт проверяет **сам текст**, а не только попадание нужной статьи в поиск.

Без модели локально формируются 79 текстов: 67 объяснений/памяток с опорой на источники, 2 организационных письма, 9 ограниченных ответов без подходящего источника и 1 уточнение. Остальные 194 имеют `requires_live_model` и **не засчитываются как успех**. Числа относятся к результату 21.10.2026, а не к любым будущим вопросам. Учебные шаблоны, хотя и проходят через код бота, не являются ответами LLM.

Флаг `--archive` отдельно анализирует сохранённые ответы модели от 12–13 октября. Исторические исходные и доработанные варианты не являются свежей проверкой сервера. Повторяющиеся тексты удаляются по хешу; отмеченные случаи требуют ручного просмотра. Готовое письмо с непривычным полем не должно ошибочно считаться отсутствующим — это проверено отдельным тестом.

Реальная генерация включается явно с настроенным доступом к тем же моделям и ключам:

```bash
python scripts/evaluate_helpfulness.py --live flowise --output /tmp/helpfulness-live.json
```

`--live flowise` требует Agentflows V2 и отправляет синтетические вопросы в Prediction API без сообщений людям в Matrix. `--live direct` проверяет прямой путь LiteLLM с этапом редактора. Перед массовым прогоном проверьте доступ и нагрузку; код не меняет выбранные модели или полномочия ключей. Полные ответы нужны для ручной проверки: смысловое соответствие, право/условия, исключения, применимость источников, полезность первого действия, сохранение контекста и качество запрошенного документа. Наличие слов и ссылки не заменяет такой разбор.

## Что добавлено по найденным проблемам

Для возврата платежа по найму есть редактируемое обращение: просьба проверить расчёты, вернуть причитающуюся сумму либо объяснить удержания и предоставить подтверждения. Это организационный образец без придуманных сроков, гарантии возврата и автоматической квалификации платежа как залога/гарантийного взноса.

Публичные тарифные PDF Halyk SuperApp, Halyk debit и Freedom retail явно разрешены обоим специалистам. Доступ к частным материалам этим не расширяется. В юридическом вопросе упоминание стоимости покупки больше не вызывает лишний вопрос о банке. Реальная генерация нового тарифного ответа остаётся непроверенной без модели.

Текущая VM недоступна. Изменения интерфейсной политики, промптов и оценки подготовлены локально; применение профилей к существующим графам Flowise и серверный прогон требуют отдельного доступа. Эти результаты не означают, что все ответы LLM уже улучшились на сервере.
