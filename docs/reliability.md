# Проверенные цитаты и восстановление запросов

## Числовые утверждения Agentflow

`numeric_grounding.py` и тот же алгоритм в `agents/quality/claim_gate.js` проверяют распознаваемые связки **показатель → число → единица → ограничение**. Например, фрагмент «Комиссия 0 тенге. Лимит перевода 100 тенге» не подтверждает ответ «Комиссия 100 тенге». Различаются валюта, рабочие/календарные дни, точное значение и «не более»/«не менее». Русские числительные и десятичные записи нормализуются.

Это дополнительный фильтр для известных названий показателей, а не универсальная проверка смысла закона. Табличная ячейка без заголовка, субъект, исключения и применимость нормы всё ещё требуют проверки моделью. Совпадение числа или буквальная цитата сами по себе не доказывают правильность вывода.

`accept_quality_response` возвращает строку `ReviewedAnswer` с `ReviewDetails`: точными выдержками, выбранными проверкой, и флагом частичного ответа. `agents.render` повторно сверяет выдержки с теми же источниками. В Element раскрываются эти выдержки целиком; другая цитата по ключевым словам не подбирается. Если после одной доработки осталась только независимая подтверждённая часть, пользователь видит **«Ответ подтверждён частично»**. Неподтверждённые строки обратно не добавляются.

Обновление уже действующих графов не требует создания новых карточек. На текущей VM скрипт уже включён в образ бота:

```sh
python /app/upgrade_agentflow_quality.py --refresh --state-dir /app/handoff_state --plan-file /app/handoff_state/claims-refresh.json
python /app/upgrade_agentflow_quality.py --refresh --state-dir /app/handoff_state --plan-file /app/handoff_state/claims-refresh.json --activate
# При необходимости:
python /app/upgrade_agentflow_quality.py --refresh --state-dir /app/handoff_state --plan-file /app/handoff_state/claims-refresh.json --rollback
```

План хранится с правами 600 вне Git. Обновление проверяет известную схему из 13 узлов и независимые изменения; сохраняет ID графов, расположение блоков, модели каждого этапа, credentials и защиту API. Используйте новый путь плана для каждого выпуска. Для переносимой Compose-сборки каталог состояния `/app/state`. Если скрипт ещё не скопирован в контейнер, выполните из корня репозитория `docker compose cp scripts/upgrade_agentflow_quality.py bot:/tmp/upgrade_agentflow_quality.py`, затем запускайте его через `docker compose exec bot python /tmp/upgrade_agentflow_quality.py` с `--state-dir /app/state` и путём плана в этом каталоге.

## Входящие сообщения и перезапуск

`matrix_inbox.py` хранит в SQLite входящие запросы, позицию `/sync`, идентификаторы обработанных событий и исходящие ответы. `matrix_delivery.py` отделяет приём событий от генерации ответа. Cursor и запросы одной синхронизации записываются одной транзакцией. Ограниченная история догружается до сохранённого события; ошибка загрузки не продвигает cursor.

При первом включении хранилища старые сообщения не обрабатываются заново. После первой успешной синхронизации вопросы, отправленные во время остановки, восстанавливаются. Для новой комнаты сообщения до вступления бота исключаются, если Matrix передал событие вступления. Комнаты сотрудников исключаются до чтения истории.

Перед отправкой сохраняются готовый текст и постоянный Matrix transaction ID. Повтор после сбоя отправляет тот же текст с тем же ID; подтверждённая отправка повторно не выполняется. Сессия Matrix восстанавливается из защищённого файла, чтобы обычный перезапуск не менял access token и область серверного удаления дублей. При отзыве токена и повторном входе гарантия Matrix по transaction ID может измениться; это не обещание абсолютного exactly-once при любых отказах сервера.

После завершения запроса его текст и содержимое исходящих сообщений удаляются из очереди. ID событий остаются для устранения дублей. Пользовательский контекст содержит до четырёх вопросов на тему, ограничен 1000 темами и сроком 30 минут; ответы модели не становятся источником фактов. `!новый` очищает контекст пользователя в этой комнате. Для повторной обработки незавершённого события сохраняется его первоначальный контекст, поэтому собственный вопрос не добавляется к истории второй раз.

В переносимом Compose файл `MATRIX_INBOX_DB=/app/state/matrix_inbox.sqlite3` находится в `runtime/bot`. На действующей VM путь по умолчанию расположен рядом с `HANDOFF_DB`: `/app/handoff_state/matrix_inbox.sqlite3`. Файл, WAL и lock относятся к приватному состоянию; база содержит сессию бота и не должна попадать в Git. Один процесс бота владеет хранилищем через файловую блокировку. Для другой учётной записи или другого сервера нужен отдельный файл.

Проверки: `tests/test_numeric_review.py`, `tests/test_matrix_delivery.py`, `tests/test_quality_refresh.py`. Они исполняют реальный JavaScript фильтра, проверяют сохранение цитат до Matrix HTML, восстановление после сбоя отправки и защиту обновления графов.
