# Работа без интернета

Локальные PDF и Flowise не заменяют модель. Для закрытой сети нужны заранее доставленные Docker-образы, Python/Node-зависимости, веса модели и работающий сервер инференса с OpenAI-совместимым API. Этот репозиторий не содержит весов и не скачивает их автоматически.

## Что подготовлено

- `config/litellm/offline.yaml`: маршруты только к локальному серверу. Все четыре совместимых имени `legal-chat*` в этом профиле ведут к **одной указанной вами модели**, а не создают четыре разных модели.
- `compose.offline.yml`: внутренний Docker network (`internal: true`), замена конфигурации LiteLLM локальным профилем.
- `scripts/offline_preflight.py`: проверка адресов upstream и выбранных имён моделей. Внешний NITEC/OpenAI endpoint в автономной конфигурации отклоняется.
- `scripts/setup.py`: при `OFFLINE_MODE=1` автоматически подключает этот профиль, не требует ключа NITEC и использует `--pull never --no-build`. Отсутствующие образы надо перенести заранее.

Статическая проверка не удостоверяет доступность модели, корректность DNS, настройки firewall или невозможность выхода из вашей инфраструктуры через прокси. Это проверяется на месте вместе с сетевым администратором. `internal: true` ограничивает сеть контейнеров; опубликованные локальные порты для пользователя остаются отдельным механизмом доступа.

## Настройка новой установки

Выполните подготовку образов и зависимостей до переноса. Для новой установки скопируйте `.env.example` в `.env`, внесите локальные параметры ниже и выполните `python scripts/setup.py init`: он заменит `GENERATE_LOCALLY` собственными случайными секретами. В закрытой сети образы должны быть загружены заранее даже для `init`. Не переносите чужие аккаунты и ключи. В своей `.env` укажите:

```dotenv
OFFLINE_MODE=1
LOCAL_LLM_BASE_URL=http://local-model:8000/v1
LOCAL_LLM_MODEL=openai/actual-served-model-id
LOCAL_LLM_API_KEY=not-required
LEGAL_LLM_MODEL=legal-chat
FINANCE_LLM_MODEL=legal-chat
GENERAL_LLM_MODEL=legal-chat
```

`actual-served-model-id` заменяется точным идентификатором, который принимает ваш сервер. `not-required` подходит только для сервера без аутентификации; иначе нужен его собственный локальный ключ. Внутри контейнеров `localhost` обозначает сам контейнер, поэтому рекомендуемый адрес — сетевой alias `local-model`.

Прикрепите контейнер с уже загруженными весами к default network данного Compose-проекта с alias `local-model`. Инференс-сервис должен слушать порт 8000 в этой сети. Не подключайте туда удалённый интернет-прокси под локальным именем. Если модель размещена на отдельном LAN-сервере, согласуйте маршрутизацию: из внутренней Docker-сети он может быть недоступен. Не отключайте изоляцию без проверки сетевой схемы.

Проверка конфигурации выполняется Python-окружением с установленными зависимостями бота (включая PyYAML):

```bash
python scripts/offline_preflight.py --env-file .env
python scripts/setup.py start
```

Для ручных команд Docker необходимо каждый раз подключать оба файла:

```bash
docker compose -f docker-compose.yml -f compose.offline.yml ps
docker compose -f docker-compose.yml -f compose.offline.yml logs --tail=100 bot litellm
```

Для Flowise добавляется третий файл `-f compose.flowise.yml --profile flowise`. Инициализируйте его локальные настройки по `docs/flowise.md` до запуска; не экспортируйте credential из прежней VM. Flowise должен обращаться к LiteLLM внутри этой же сети. Скрипты обслуживания Flowise сами по себе не являются проверкой автономности: используйте согласованную Compose-конфигурацию для каждого запуска.

## Приёмка на сервере

1. Убедиться, что `/v1/models` и `/v1/chat/completions` локального инференса доступны из сети LiteLLM, а извне не используются модельные провайдеры.
2. Проверить вход в Element, поиск по локальной базе и оба Agentflows V2. Выполнить несколько разных вопросов, включая повторное уточнение и составление документа.
3. Отключить внешний канал на уровне сети и повторить те же вопросы; проверить журналы/сетевые соединения. Статический preflight этого не заменяет.
4. Отдельно проверить переход к любому из пяти сотрудников каждого департамента, смену сотрудника и сохранение истории.
5. Проверить фактическую скорость и одновременную работу пользователей на выбранном железе. Количество CPU/GPU и размер модели определяют качество и задержку; 500 обращений в день этой локальной проверкой не подтверждены.

На 21.10.2026 новая конфигурация проверена локально на структуру, адреса и ограничения. Реальная модель, Docker-контейнеры и VM в этом прогоне недоступны: автономная приёмка пока не выполнена.
