# Что проверить специалистам в первую очередь

Статус: **кандидаты, экспертного подтверждения нет**. Ответственные юрист и финансист пока не назначены. Автоматические критерии и совпадение цитат не доказывают правильность правовой интерпретации.

Начните с закрытого пакета `runtime/evaluation/specialist-review-refinement-20261024`. Он содержит публичные вопросы, источники и хеши ответов. Тексты ответов в пакет не копируются: проверяющий открывает исходный закрытый отчёт на VM и сверяет хеш. Старые пакеты и заполненные формы не заменяются.

## Приоритетные предметные проверки

| Группа | Что требуется подтвердить по существу |
|---|---|
| Брачный договор | Различение имущественного положения детей и ограничений регулирования прав и обязанностей супругов в отношении детей; отсутствие расширительного пересказа. |
| Место жительства ребёнка | Различение учёта мнения, интересов ребёнка и порядка разрешения спора; отсутствие вывода, что один возраст сам по себе решает вопрос. |
| Чужой долг и угрозы взыскателя | Отдельно основание обязанности пользователя, допустимость взаимодействия и меры безопасности; родство не использовать как готовую правовую квалификацию. |
| Кредитная история | Адресат обращения, спорная запись, подтверждения и результат проверки; не обещать удаление достоверной истории. |
| Проект заявления | Есть пригодный черновик с заполнителями; обязательные поля и реальные требования различаются с пожеланиями заявителя; нет выдуманного срока. |
| Долевое строительство | Документы и условия соответствуют конкретному способу привлечения денег; не смешаны условия разных способов. |
| Удержание из страховой выплаты | Проверен вид расходов, субъект и условие применимости; общая норма о страховом случае не подменяет норму о расходах. |
| Дивиденды | Учтён вид акций и подтверждённые условия решения; общее правило не перенесено без проверки на исключение. |
| Цифровые активы | Использована классификация из применимой редакции, а не подмена старого термина новым или обещание доходности. |
| Банковский тариф | Совпадают банк, операция, канал, категория клиента, условия строки и дата. Техническая сверка PDF не считается заключением финансиста. |

## Как фиксировать решение

1. Сначала проверьте кандидатный эталон и пригодность автоматических критериев для вопроса.
2. Затем сопоставьте ответ с полной нормой, связанными положениями, исключениями и датой действия. Укажите конкретные статью/пункт и условия применимости.
3. В `review-template.json` заполните ФИО, роль, решение и замечания. Для ответа поставьте три оценки 0–4: точность, полезность, сохранение исключений.
4. Для отклонения укажите существенную ошибку и предложенную формулировку. Для одобрения каждая оценка должна быть не ниже 3. `reviewed_by_human=true` выставляется только после реальной проверки.
5. Импортируйте решение через `scripts/specialist_packet.py import` по инструкции в [quality-program.md](quality-program.md). Изменённые вопрос, корпус или ответ требуют новой проверки.

Ориентиры: **4** — существенных замечаний нет; **3** — небольшие исправления без изменения вывода; **2** — пропущено существенное условие или ответ мало помогает; **1** — существенная ошибка/почти нет помощи; **0** — неприемлемый или потенциально опасный ответ. Это рабочая шкала, не автоматическая правовая сертификация. Импорт фиксирует заявленную оператором личность и сам по себе её не удостоверяет.

## Предложения по критериям не приняты автоматически

`config/answer-criteria-proposals.json` отдельно предлагает исправить буквальные требования к формулировкам. Исходный набор `config/model-challenge-cases.json` сохранён. Скрипт `scripts/compare_answer_criteria.py` считает обе версии на **одних и тех же ответах**, без копирования их текста. Разницу этих оценок нельзя объявлять улучшением модели. Удаление проверки исправления записи из вопроса только о получении отчёта также требует содержательного согласия проверяющего.
