# Flowise: отдельный пилот для Element

Multica удалена из исполняемого кода бота. Основные комнаты по умолчанию используют прежний прямой вызов LiteLLM.

В пилотной комнате путь запроса такой:

```text
Element → Synapse → Python-бот → поиск в локальных PDF/TXT
                            → Flowise → LiteLLM → модель
                            ← проверка ответа и цитат ←
Element ← Synapse ← оформленный ответ
```

Это первый этап: в Flowise перенесена генерация и повторная проверка ответа моделью. Поиск по PDF, отбор источников, форматирование, проверка цитат и передача живому сотруднику остаются в Python-боте. Документы не обучают веса модели. При отсутствии подходящих документов бот может ответить без вызова Flowise.

## Ограничение Flowise

Официальный проект [архивирован, поддержка завершена 31 августа 2026](https://github.com/FlowiseAI/Flowise/discussions/6727). Здесь закреплён образ **3.1.4** по digest. Пилот слушает только `127.0.0.1:13001`; не публикуйте его напрямую в интернете. SQLite в этом образе вызывает ошибку хранилища сессий, поэтому используется отдельная PostgreSQL.

## Установка после обычного setup.py

```bash
python3 scripts/init_flowise.py
docker compose -f docker-compose.yml -f compose.flowise.yml --profile flowise up -d flowise
docker compose cp scripts/setup_flowise.py bot:/tmp/setup_flowise.py
docker compose exec bot python /tmp/setup_flowise.py --prepare-only
```

Администратор создаётся автоматически; данные входа — в `runtime/bot/flowise_admin.json`, не в Git. Flowise открывается на http://localhost:13001. При работе с VM нужен отдельный туннель с Mac:

```bash
tsh ssh -N -L 13001:127.0.0.1:13001 admin_sts@sts-vm-06
```

Новый сервис не подключается к уже существующей установке Flowise других проектов. Если LiteLLM расположен во внешней Docker-сети, подключите только новый сервис Flowise к этой сети, сохранив имя `litellm` и разрешённый модельный псевдоним.

## Доступ к модели и создание потоков

Предоставьте **отдельный виртуальный ключ LiteLLM для Flowise**, ограниченный нужными моделями. Мастер-ключ и ключ поставщика в Flowise передавать не требуется. Размещение ключа в новом сервисе должно быть явно разрешено владельцем. Скрипт не читает существующий ключ бота.

Сохраните выделенный ключ в закрытом файле `runtime/bot/flowise_llm_key` (права `600`), затем:

```bash
docker compose exec bot python /tmp/setup_flowise.py --llm-key-file /app/state/flowise_llm_key
```

Создаются два редактируемых в интерфейсе потока: **STS Flowise — ЮрАгент**, **STS Flowise — ФинАгент**. Каждый содержит Prompt Template → ChatOpenAI → LLM Chain. `basepath` направлен на LiteLLM; модель берётся из `LEGAL_LLM_MODEL` / `FINANCE_LLM_MODEL` на момент создания. Изменения модели в `.env` не меняют уже созданные потоки: настройте их в Flowise. Повторный запуск сохраняет существующие потоки.

Отдельный ключ Prediction API обязателен и сохраняется в `runtime/bot/flowise_api_key`; потоки не публичные. Flowise хранит зашифрованные учётные данные, запросы и ответы в своей базе. Том данных и ключ шифрования нужно резервировать вместе. Не передавайте реальные персональные данные в пилоте.

## Включение только тестовой комнаты

Создайте незашифрованную тестовую комнату в Element, пригласите `@bot:demo.local`. Возьмите идентификатор комнаты из её настроек. В `runtime/bot/flowise_setup.json` находятся идентификаторы созданных потоков. Создайте `runtime/bot/flowise_rooms.json`:

```json
{
  "!TEST_ROOM:demo.local": {
    "domain": "legal",
    "flow_id": "UUID юридического потока"
  }
}
```

```bash
docker compose up -d --build bot
```

В логе должен появиться `Flowise pilot rooms configured: 1`. Отправьте содержательный вопрос по документам и дождитесь нового ответа. Запись `Flowise response received; domain=legal` подтверждает вызов Flowise; сама загрузка интерфейса этого не доказывает. Проверьте также обычную юридическую и финансовую комнаты и команду `!человек`.

Комнаты и роли изолированы: финансовый поток не вызывается для юридического маршрута. История других пользователей не передаётся. Потоки создаются без памяти; бот передаёт нужный контекст и выдержки источников. Обработка ответа остаётся общей с прямым LiteLLM. Flowise API не предоставляет здесь достоверный `finish_reason`, поэтому автоматическое определение обрыва по лимиту токенов ограничено.

## Отключение

Замените содержимое `runtime/bot/flowise_rooms.json` на `{}` и перезапустите **только бот**. Все комнаты вернутся к прежнему прямому LiteLLM. Остановка Flowise при включённом маршруте показывает ошибку сервиса; скрытой подмены ответа другой моделью нет.

Исторические отчёты про Multica сохранены как история проекта. Они не означают, что действующий бот её вызывает.

## Результат пилота на VM от 09.10.2026

Созданы отдельные комнаты **STS — ЮрАгент — Flowise (тест)** и **STS — ФинАгент — Flowise (тест)**. Пользователь `@support-demo:demo.local` (отображаемое имя `ruslan`) приглашён в обе; приглашения нужно принять в Element. Основные комнаты сохранили прямой маршрут LiteLLM.

С разрешения владельца создан отдельный ключ LiteLLM: только `legal-chat-qwen38-int4`, только chat completions, 30 запросов/минуту, максимум два параллельных запроса. Срок действия до **08.11.2026 05:53 UTC**; до этой даты ключ необходимо обновить в закрытом файле и в учётных данных Flowise. Скрипт настройки сохраняет существующие credentials; для ротации обновите их через интерфейс Flowise. Старый ключ бота, ключ поставщика и master key не переносились в Flowise.

Через Matrix отправлены два синтетических вопроса: о возрасте вступления в брак и комиссии Halyk SuperApp за коммунальные услуги. Оба ответа содержали нужные сведения из локальных документов, цитаты, HTML-оформление и подсказку передачи человеку. Логи подтверждают вызовы Flowise для черновика и проверки. Юридический ответ потребовал автоматической повторной попытки после проверки цитат. Временный тестовый пользователь деактивирован. Браузерное отображение и новое обращение живому сотруднику в этом прогоне отдельно не проверялись.

Выявленные ошибки поиска исправлены: нужная статья семейного кодекса повышается в выдаче для вопроса о брачном возрасте; явно указанный SuperApp ограничивает набор документов до выбора первых результатов, нужная строка тарифа учитывает переносы PDF. Проверки источников и запрет подменять тариф другим продуктом сохранены. 131 автоматический тест прошёл. Подробности: [отчёт](../reports/flowise-pilot-20261009.json).

## Проверка без настоящего LLM-ключа

```bash
docker compose cp scripts/setup_flowise.py bot:/tmp/setup_flowise.py
docker compose cp scripts/check_flowise_transport.py bot:/tmp/check_flowise_transport.py
docker compose exec bot python /tmp/check_flowise_transport.py
```

Тест создаёт временный защищённый граф и модель-заглушку внутри сети контейнеров. Проверяет блокировку запроса без ключа, вызов графа с правильным ключом и сохранение метки `[S1]`, затем удаляет созданные объекты. В версии 3.1.4 ошибка Unauthorized обёрнута в HTTP 500; отсутствие вызова модели проверяется отдельно. Это проверка транспорта, а не качества ответов реальной модели и не полный тест переписки в Element.
